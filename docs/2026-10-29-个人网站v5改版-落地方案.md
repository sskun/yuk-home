# 个人网站 v5 改版落地方案

## 1. 背景与目标

外部设计交付物在 `/Users/yukun/WorkBuddy/2026-10-29-14-36-22/个人网站-v5/交付`，包括 7 份规格文档、7 个视觉稿 HTML、`视觉稿/assets/page.css` 和 7 张导出图。设计把站点从"个人作品门户"改成"AI 工具情报站"：首页第一屏是站内检索框，全站有情报流、工具库、文章、项目、关于 5 个栏目。

本方案说明如何在当前仓库落地这套设计。当前仓库是 Astro 7.0.7，静态输出，部署在 Cloudflare Pages。方案同时照顾三个视角：

- **访客**：第一屏就能搜，任何页面按 `/` 都能搜；点一次就能到达目标（原始来源、工具官网、文章正文）；页面切换几乎没有等待；手机上信息不丢失。
- **视觉**：以视觉稿为准，全站只有一种强调色，靠排版区分栏目。动效要做得高级，但不破坏这套克制的视觉语言。偏离设计稿的地方逐条列在第 4 节。
- **架构**：纯静态，零后端；内容就是文件；派生数据在构建时计算；检索在浏览器里完成；mock 数据可以一键清掉；技术选型跟随 Astro 生态的主流方案。

## 2. 已确认的决定

| 项 | 决定 |
|---|---|
| 运行形态 | 纯静态，不使用数据库和服务端函数 |
| 订阅 | 全部去掉，包括顶栏按钮、每页订阅条和侧栏订阅框 |
| 个人信息与内容 | 先用 mock，可以自由发挥，统一打上 `mock: true` 标记 |
| 项目 | TraceMine 和图片治理按现有真实功能来写；第三个项目是 yuk-home 本站 |
| 文章 | 保留 `/article` 路由和现有字段，`docs/article-admin.md` 里规划的后台能力继续有效 |
| `/tools` | 改为工具库；`/tools/image-governance` 地址不变，并按新设计**整体重构界面，功能全部保留** |
| 样式 | 用 Tailwind CSS v4 承载设计令牌，组件库用 Starwind UI，去掉 daisyUI（见 6.2） |
| 动效 | 用 Astro 视图过渡、GSAP 和 CSS 滚动驱动动画（见 6.3） |
| 旧代码 | 删除配置驱动的首页体系 |
| 分支 | 在当前分支 `home-style-v1` 上直接做 |

## 3. 能力边界

### 3.1 静态可以实现（本轮全部做）

| 能力 | 实现方式 |
|---|---|
| 7 个页面的视觉和动效 | Tailwind v4 + Starwind UI + GSAP + 视图过渡 |
| 四类内容 | 内容集合，构建时用 zod 校验 |
| 页头统计、chips 计数、按天或按年分组、文章编号、字数、阅读时长、连续更新周数 | 构建时计算 |
| 全站检索 | 构建时输出 `/search-index.json`，浏览器端用 BM25 检索 |
| 筛选、排序、加载更多、锚点定位 | 少量 TS 脚本作用在已渲染的 DOM 上 |
| "今日 / 本周"相对时间 | 浏览器端用条目日期现算；构建产物里的绝对日期作为无 JS 时的回退 |
| SEO：title、description、og、canonical、JSON-LD、sitemap、robots、RSS | 静态接口加 `public/` 下的文件 |
| 图片治理（裁剪、压缩） | 浏览器端完成，沿用现有 Worker 和算法 |

### 3.2 静态拿不到真实值（本轮改成手填或去掉）

| 设计里的内容 | 处理方式 |
|---|---|
| 情报"最热"、工具"用得最多"排序 | 去掉。没有访问数据，假排序会误导访客 |
| 文章"读得最多" | 改成"推荐阅读"，由 frontmatter 的 `pick: true` 决定 |
| 项目"在线"状态点 | 手填 `status` 字段 |
| 累计安装量 | 先用 mock。以后可以在构建时调 npm 公开接口取真实值（实测 tracemine 近一年下载 496 次，不需要账号） |

### 3.3 需要外部支持（本轮不做，列出供以后决定）

| 能力 | 需要准备 |
|---|---|
| 订阅 | Buttondown 等邮件服务账号；或者自建 Workers + D1/KV 加发信服务（这是唯一需要数据库的方案） |
| 真实热度排行 | Cloudflare Web Analytics 加 API Token，构建时拉数据；或者 Workers + KV/D1 自建计数器 |
| 在网页或手机上发内容 | 按 `docs/article-admin.md` 实现后台（Pages Functions、Cloudflare Access、GitHub Fine-grained Token），并扩展到情报集合 |
| 情报自动采集、AI 摘要 | GitHub Actions 或 Workers Cron 定时任务、来源清单、LLM API Key |
| 域名 yukxai.top 和域名邮箱 | 购买域名，在 Pages 绑定，用 Email Routing 转发邮件；之后修改 `astro.config.mjs` 的 `site` |
| 真实截图和头像 | 由你提供，放到 `src/assets/` |

日常更新流程：写 md 文件 → `git push` → Pages 自动构建。免费版每月可构建 500 次，按每天推 4 次算约 120 次，够用。

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 首页 | 检索台 |
| `/feed` | 情报流 | 条目锚点 `/feed#<id>` |
| `/tools` | 工具库 | 条目锚点 `/tools#<id>` |
| `/tools/image-governance` | 图片治理 | 地址不变，界面重做 |

| `/search-index.json` | 检索索引 | 静态接口生成 |
| `/rss.xml`、`/sitemap.xml`、`/robots.txt` | SEO | RSS 只放在 `<head>` 和页脚的小链接里，不做订阅界面 |
| `/404` | 404 | Pages 自动使用 |

导航高亮：按路径前缀匹配，首页不高亮任何一项。

一键触达规则：

- 情报标题链接到 `sourceUrl`，新标签页打开，带 `rel="noopener noreferrer"`；来源为"本站"的条目链到站内。
- 工具的"打开"直接去官网；我自己做的工具链到站内页面。
- 检索结果跳到站内锚点。如果目标被"加载更多"折叠了，先自动展开，再滚动过去并高亮 2 秒。
- 筛选和排序状态写进 URL 参数（如 `?cat=模型&sort=new`），可以分享，后退时能还原。
- 站内链接悬停时预取，配合视图过渡，切换页面基本感觉不到加载。

### 6.2 样式与组件选型

**结论：继续用 Tailwind CSS v4，设计令牌写进 `@theme`；组件库用 Starwind UI；去掉 daisyUI。**

| 方案 | 结论 | 原因 |
|---|---|---|
| Tailwind CSS v4（4.3.3，仓库已装） | **采用** | Astro 生态里最主流的样式方案；v4 在 CSS 里直接配置，`@theme` 能一比一承载设计令牌；在构建时按需生成，体积可控 |
| Starwind UI（CLI 3.4.1） | **采用** | 为 Astro 原生打造、shadcn 风格的组件库，基于 Tailwind v4，组件自带动画和无障碍支持。CLI 把源码拷进项目，我们可以完全改成设计稿的样子，不依赖黑盒 |
| shadcn/ui（React） | 不用 | 需要 React islands，会给内容站多加一个 React 运行时，对首屏性能不划算 |
| daisyUI | 去掉 | 它是主题式组件，视觉风格和本设计不搭；类名太通用，仓库已经因为它撞过三次样式（见 `global.css` 注释） |
| bejamas/ui | 备选 | 同样是 Astro 原生、零 JS 的 shadcn 风格组件库，社区较小。如果 Starwind 在 P0 验证不兼容 Astro 7，就换用它 |

设计规格里写"不引 Tailwind / UI 库"，是担心照着手写 CSS 改写时走样。规避办法如下：

- **令牌一比一**：把 `01-设计令牌.md` 的颜色、字体、圆角、阴影都写进 `@theme`（如 `--color-ink`、`--color-blue-soft`、`--font-mono`、`--radius-card: 12px`）。设计里的非整数字号（9 / 9.5 / 10.5 / 12.5 / 13.5 等）定义成具名字号（如 `text-meta`、`text-body`），不在页面里随手写任意值。
- **只有一个断点**：设计以 1080px 为界。定义 `--breakpoint-desk: 1081px`，移动优先，统一用 `desk:` 前缀。
- **重复模式封装成 Astro 组件**（卡片、chip、kick、分组标题），不大量使用 `@apply`。
- **正文排版单独写在 `prose.css`**，按规格 E 节的数值写死，不用 `@tailwindcss/typography`，因为它的默认值需要大量覆盖。
- **Starwind 主题变量**（`--primary`、`--border`、`--ring`、`--radius` 等）全部映射到设计令牌，组件自然继承设计稿的外观。
- **启用 Tailwind 的 preflight**：页面全部重写，过去为兼容旧样式而关掉它的理由已经不存在。
- **验收**：用 DOM 测量核对关键尺寸，不靠肉眼比对。

用到的 Starwind 组件：Dialog（检索浮层）、Sheet（移动端导航抽屉）、Tabs、Slider、Input、Button、Badge、Toggle（chips）、Tooltip、Alert、Progress、Toast（后五个主要用在图片治理页）。

### 6.3 动效方案

**结论：分三层，各取所长。**

| 层 | 选型 | 负责什么 |
|---|---|---|
| 页面切换 | Astro 内置 `<ClientRouter />` 视图过渡，加悬停预取 | 页面之间交叉淡入，顶栏保持不动；文章卡的标题过渡成详情页 h1，项目卡过渡成项目块。不需要额外依赖 |
| 编排动效 | GSAP 3.15 | 2025 年起全部插件免费，可商用。本站用到 SplitText（逐字出现）、ScrollTrigger（进入视口）、Flip（筛选时列表平滑重排），都按页面懒加载 |
| 简单的连续动效 | CSS 滚动驱动动画 `animation-timeline` | 阅读进度条、顶栏滚动后出现底边。全球支持率约 83%，用 `@supports` 包住，不支持的浏览器保持静态 |

去掉现有依赖 `motion`。它的布局动画只有 React 版本，满足不了"筛选时列表重排"这个需求，也没必要同时维护两套动画库。

**动效清单（你可以逐条否决）**

| 位置 | 效果 | 时长 |
|---|---|---|
| 页面切换 | 内容区淡入并上移 8px；文章卡标题和详情页 h1 之间形变过渡 | 250ms |
| 首页 hero h1 | 逐字上浮出现，同一会话只播放一次 | 共 700ms 以内 |
| 首页大检索框 | placeholder 轮播 4 个示例问题（打字效果），获得焦点即停止 | 每条 3s |
| 首页数据卡 | 进入视口时数字从 0 滚动到目标值 | 600ms |
| 卡片和列表行 | 首次进入视口时错位淡入（每批之间相隔 40ms） | 300ms |
| chips 筛选和排序 | 保留的行平滑移到新位置，被滤掉的行淡出 | 300ms |
| 检索浮层 | 缩放淡入；结果逐条出现；用 ↑↓ 选择时，高亮块滑动跟随 | 200ms |
| 卡片悬停 | 上移 2px，边框加深（设计稿原有） | 150ms |
| 锚点定位 | 目标行蓝底闪一下后褪去 | 1.5s |
| 阅读进度条、顶栏底边 | 跟随滚动 | 实时 |
| 图片治理 | 拖入图片时上传区边框呼吸；处理进度条；原图与结果对比滑块；结果数字滚动 | 300ms |

**不做的效果**：渐变光晕、玻璃拟态、视差背景、鼠标跟随、滚动劫持（ScrollSmoother）、加载闪屏。它们和设计语言冲突，也会拖慢访客找到内容的速度。

**规则**：

- 动效只是增强。内容默认可见，JS 加载后才设置动画的初始状态，禁用 JS 时内容完整显示。
- 系统开启"减少动效"时，所有动画关闭，视图过渡也退化为直接跳转（ClientRouter 自带这一行为）。
- 单个交互动效不超过 400ms，不阻塞点击。
- GSAP 及其插件只在用到的页面动态引入，不进首屏的关键路径。

**ClientRouter 的配套要求**：页面切换后脚本不会自动重新执行。所有初始化统一注册在 `lifecycle.ts` 的 `astro:page-load` 事件上，切换前在 `astro:before-swap` 里清理 ScrollTrigger 和事件监听。全局快捷键只注册一次。图片治理页使用 Worker 和大量 blob URL，进出这个页面时做整页刷新（`data-astro-reload`），避免状态残留。

### 6.5 构建期派生数据

`lib/stats.ts` 只接收数组、返回数值，不依赖 `astro:content`，方便单独测试。统计内容包括：各类总数、分类计数、本周新增、日均条数、来源数、连续更新周数、总字数、按年计数等。其中本周新增按构建时间计算，浏览器端再按当前时间覆盖。

### 6.6 检索

- **索引**：`src/pages/search-index.json.ts` 在构建时读取 4 个集合，只输出检索需要的字段。
  - 情报：标题、摘要、判断。
  - 文章：标题、描述、判断、正文前 800 字。
  - 工具：名称、一句话介绍、标签。
  - 项目：名称、一句话介绍、正文前 600 字。
  - 不另写构建前脚本，也不引入 `gray-matter`。
- **算法**：沿用规格 05 的分词和 BM25，标题权重 ×3；命中标签再额外加分，让"本地优先"这类词优先召回对应的工具。
- **加载**：页面空闲时预取索引，检索框获得焦点时立即拉取，建好的索引留在内存中。使用 ClientRouter 后，切换页面不必重新加载索引。
- **入口**：
  - 首页大检索框：结果内联显示在框下方，每组最多 3 条，组尾有"查看全部 N 条"，点击后打开浮层并带上当前查询。
  - 内页检索栏、顶栏"搜索"按钮、快捷键 `/` 和 `Cmd/Ctrl + K`：都打开 Starwind Dialog 浮层。输入框聚焦时不响应快捷键。
- **交互**：结果按情报、工具、文章、项目分组并显示条数；↑↓ 选择，Enter 打开，Esc 关闭；关闭后焦点回到触发元素。
- **空态**：空查询时显示 4 个推荐词；无结果时提示"没有匹配"，同时给出推荐词。
- **安全**：先对摘要做 HTML 转义，再插入 `<mark>`。
- **无 JS**：检索框提示"检索需要开启 JavaScript"，页面其余部分正常使用。
- **扩展**：1,800 条以内不分片；超过后按年分片，并把建索引挪到 Web Worker。

### 6.7 列表交互

- **情报流**：默认显示 14 条，每次加载更多 14 条；chips 可多选（同组内是"或"，"我的判断"与分类之间是"且"）；排序只保留"最新"和"仅带判断"；计数随筛选结果更新；重排时用 GSAP Flip 过渡。
- **工具库**：排序有"最近验证"和"最近新增"；默认显示 16 个，"显示全部"展开其余。
- **文章列表**：浏览行按年份或分类显示和隐藏，不分页。
- **无 JS**：全部条目可见，隐藏 chips 和排序控件。
